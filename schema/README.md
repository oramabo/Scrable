# `schema/` — the Dart ⇄ TypeScript contract

These JSON Schemas (draft 2020-12) are the single source of truth for every
JSON document that crosses the boundary between the Dart code
(`packages/core`, `apps/*`, `tools/generate`) and the TypeScript Cloud
Functions (`functions/`). **The Dart codec output defines the schema, not the
other way round**: when `packages/core` changes what it serialises, update the
schema in the same change and regenerate the fixtures.

| Schema | Produced by | Consumed by |
|--------|-------------|-------------|
| `puzzle.schema.json` (format 1 objects or compact format 2 `clues` arrays) | `PuzzleCodec.toJson` (`packages/core/lib/src/model/puzzle_codec.dart`) | app (play), admin (preview), `publishPuzzle` (validation before upload), content CI |
| `progress.schema.json` | `PuzzleProgress.toJson` (`packages/core/lib/src/engine/progress.dart`) | app local save (drift), cloud sync `users/{uid}/progress/{puzzleId}` |
| `ledger-entry.schema.json` | app wallet (client-authored, UUID v7 ids) | `syncLedger` function, Firestore rules for `users/{uid}/ledger/*` |
| `daily-manifest.schema.json` | `chetz_gen manifest` (content pipeline) and `rebuildManifests` function → `manifests/{lang}/daily.json` | app content module |
| `packs-manifest.schema.json` | `chetz_gen manifest` and `rebuildManifests` → `manifests/{lang}/packs.json` (packs with their puzzle lists inline, localised `title`) | app content module |
| `publish-index.schema.json` | `chetz_gen manifest` → `content/{lang}/puzzles/manifests/publish-index.json` (per-puzzle `solutionHash`, `letterCells`, checksum, file) | publisher → `publishPuzzle` function; never shipped |
| `manifest.schema.json` | union of the three manifest schemas (convenience) | tooling |

## Fixtures

`fixtures/` holds documents that are valid against their schema and are used by
CI and by the functions' unit tests:

- `puzzle-daily-he-v2.json`, `puzzle-pack-he-v2.json` — the same two puzzles in format 2 (`chetz_gen convert`); same solution hash.
- `puzzle-daily-he.json`, `puzzle-pack-he.json` — generated by the real Dart
  generator + codec from the Hebrew lexicon (obfuscated `xor1` solution,
  checksum set by `PuzzleCodec.withChecksum`). `puzzle-daily-he.solutionHash.txt`
  is `PuzzleCodec.solutionHash` of the daily, used to prove the TypeScript port
  (`functions/src/lib/puzzleCodec.ts`) is byte-identical with the Dart codec.
- `progress-he.json` — `PuzzleProgress.toJson` for the daily fixture.
- `ledger-entry-*.json`, `daily-manifest-he.json`, `packs-manifest-he.json` — hand-written.
- `publish-index-he.json` — two rows taken from the real `chetz_gen manifest` output.

Fixture file names are mapped to schemas by prefix (`puzzle-`, `progress-`,
`ledger-entry-`, `daily-manifest-`, `packs-manifest-`, `publish-index-`).

## Validate

```sh
npm ci --prefix schema                    # or: npm ci --prefix functions (the validator falls back to it)
node schema/validate.mjs                  # compiles every schema and validates every fixture
node schema/validate.mjs --content content   # ... plus every generated puzzle and manifest under content/*/puzzles
```

`validate.mjs` also runs structural checks the schema cannot express for
puzzles (layout vs. grid size, solution length vs. letter cells, word/clue slot
cross references). `ci-functions.yml` runs the fixture pass on every push and
`content-validate.yml` runs the `--content` pass; at the time of writing all
870 generated puzzles (he + en, dailies + packs) and the three manifests pass.

## Conventions worth knowing

- Grid column `0` is the **first column in reading direction** (rightmost for
  Hebrew, leftmost for English); `grid.colOrigin` is always `"readingStart"`.
- `solution.enc = "xor1"`: base64 of the letter-cell symbols XOR-ed with a
  SHA-256 keystream of `"{id}|chetz-v1|{counter}"`. Obfuscation, not secrecy.
- `meta.checksum = "sha256:<hex>"` over the canonical JSON (sorted keys, no
  whitespace, integral doubles written as integers) of the puzzle with a
  *plain* solution and `meta.checksum` removed.
- Dart emits doubles such as `22.0`; JSON Schema `number` accepts both forms.
- Progress cell entries use compact keys (`s`, `st`, `p`, `t`) and the status
  codes `empty|filled|correct|wrong|revealed`.
- Manifest `url`s are paths relative to the CDN root (`puzzles/he/daily/easy/2026-11-01.v1.json`);
  the app prefixes its configured base URL. Absolute `https://` URLs are also accepted.
  Pack puzzle files are zero-padded (`01.v1.json`); the pack file is `pack.v1.json`.
- Ledger entry ids are UUID v7 for client entries; server-authored entries
  (`rc_<revenuecat event id>`, `starting_wallet`) live in the same collection
  and carry a `server` block that clients must never send.
